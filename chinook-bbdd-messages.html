El hosting de AWS es case-sensitive (al igual que algunos otros hosting, por lo tanto vuestra primera tarea será editar los nombres de campos en las tablas que se usarán para el proyecto y dejar todos los nombres estandarizados antes de proceder a importar la Base de Datos y comenzar el producto uno. Para realizar ésta tarea, podéis abrir los archivos en VSCode u otro editor de código. Las Tablas para la Base de Datos Chinook se encuentran en Contenidos, sección Fase 3. Desarrollo

El uso de snake_case en minúsculas es considerado la mejor práctica estándar para nombrar objetos en bases de datos (tablas, columnas, índices, etc.) en la mayoría de los sistemas relacionales. Esta convención consiste en separar las palabras mediante guiones bajos (_) y utilizar minúsculas para todos los caracteres.

A pesar de que muchos motores de Bases de Datos tratan los nombres como minúsculas automáticamente o no distinguen entre mayúsculas y minúsculas, otros sí que dan problemas, con lo cual es importante respetar el estándar.

Mejores prácticas para evitar errores de naming al migrar una BBDD

  • Tablas (Plural): Usar sustantivos en plural para las tablas (ej: users, customer_orders).
  • Columnas (Singular): Use sustantivos en singular para las columnas (ej: first_name, user_id).
  • Caracteres: Tanto en los nombres de tabla como los de las columnas, utilizar solo minúsculas (a-z), números (0-9) y guiones bajos (_).
  • Evitar palabras reservadas: No utilizar nombres que sean palabras clave de SQL (ej: order, select).

Utilizar las mejores prácticas descritas anteriormente, además de evitar errores al migrar otorga legibilidad en las consultas al ofrecer un contraste visual claro con las palabras clave de SQL (que se suelen escribir en MAYÚSCULAS) y compatibilidad al ser la convención más compatible entre sistemas operativos y ORMs (Object-Relational Mappers).

Recomendación: Probar y revisar en local ( material en anuncio [Fase 1]. Preparación del Entorno de Trabajo ) la importación de las tablas, antes de pasarlas a la Base de Datos compartida.

Es deseable que realicen ésta actividad antes de las videoconferencias para poder resolver cualquier duda que se presente.

Para ejecutar los script SQL (.sql) corregidos que contienen las tablas de la BBDD en MySQL Workbench, deberéis conéctaros a la base de datos (local o AWS) e ir a File > Open SQL Script... para ir seleccionando los archivos. Luego, hacer clic en el icono del rayo (Execute) en la barra de herramientas para importar la tabla pertinente. La BBDD de AWS ya tiene un nombre (que no podéis cambiar), en el caso del servidor local, deberéis crear una BBDD para poder realizar la importación de las tablas en la misma.
